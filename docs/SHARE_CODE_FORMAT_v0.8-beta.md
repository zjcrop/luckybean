# Lucky Bean `LB8` 分享编码格式

版本：`1`  
适用应用：富贵盒子 `0.8.0-beta.1`

## 1. 设计目标

`LB8` 用于在浏览器链接和二维码中携带豆卡、冲煮方案和品鉴记录。设计原则：

1. 咖啡基础字段直接沿用 BrewIon 的国家、产区、实体、豆种、处理法、烘焙度和风味代码；
2. 高频术语使用固定字典，不重复写入中文长文本；
3. 冲煮分段使用定长意义明确的数组；
4. 先做结构压缩，再使用浏览器原生 Deflate/Gzip；
5. 不包含邮箱、手机、微信、QQ和本机备注；
6. 链接仅携带最近5条冲煮与5条品鉴，完整历史通过备份文件迁移。

## 2. 外层前缀

```text
LB8R.<base64url>  Deflate Raw
LB8D.<base64url>  Deflate
LB8G.<base64url>  Gzip
LB8J.<base64url>  未压缩JSON回退
```

解码器按前缀选择算法。编码后二进制使用 Base64URL，删除尾部 `=`。

## 3. 顶层对象

| 短键 | 含义 |
|---|---|
| `v` | 分享格式版本，当前为1 |
| `a` | 应用版本 |
| `d` | 分享日期，`YYMMDD` |
| `u` | `[个人公开ID, 昵称]` |
| `b` | 豆卡数组 |
| `r` | 冲煮记录数组，最多5条 |
| `s` | 品鉴记录数组，最多5条 |

## 4. 豆卡数组 `b`

```text
[
  国家代码,
  产区代码,
  庄园/处理站代码,
  豆种代码,
  处理法代码,
  烘焙度代码,
  烘焙日期YYMMDD,
  风味代码数组,
  烘焙色值,
  显示名称
]
```

前8类代码均与 BrewIon 数据表保持一致。显示名称是容错字段；正常解码时应优先通过代码表显示标准名称。

## 5. 冲煮记录 `r`

每条冲煮记录：

| 短键 | 含义 |
|---|---|
| `i` | 记录ID |
| `d` | 创建日期 |
| `e` | 引擎版本 |
| `p` | 方案字典码 |
| `t` | `[粉量, 水量, 粉水比, 总时长秒]` |
| `s` | 分段数组 |
| `w` | 水质简表 |
| `g` | 研磨简表 |
| `f` | 风味拟合百分数 |
| `c` | 修正来源与修正说明 |

### 5.1 方案字典 `p`

| 码 | 方案 |
|---:|---|
| 0 | 模型推荐 |
| 1 | 一刀流 |
| 2 | 两段式 |
| 3 | 三段式 |
| 4 | 四六法 |
| 5 | 46法·平底净化 |
| 6 | 五段式 |
| 7 | 30g/15秒固定脉冲 |

### 5.2 分段数组

```text
[阶段秒数, 本段克重, 注水法两位码, 水温°C, 排水等待秒数, 扰动码]
```

累计注水量由各段克重顺序相加，不重复存储。

### 5.3 注水法两位码

第一位表示路径：

| 第一位 | 注水方式 |
|---:|---|
| 1 | 中心注水 |
| 2 | 绕圈注水 |
| 3 | 中心向外绕圈 |
| 4 | 外圈向中心绕圈 |
| 5 | 浸泡/搅拌 |
| 6 | 截流/排空 |

第二位表示流量：

| 第二位 | 流量等级 |
|---:|---|
| 1 | 小流量，约3.0g/s及以下 |
| 2 | 中流量，约3.7–5.2g/s |
| 3 | 大流量，约5.3g/s及以上 |

示例：`33` 表示“中心向外绕圈，大流量”。

### 5.4 水质简表 `w`

```text
[水质方案ID, TDS中值, Ca mg/L, Mg mg/L, HCO3 mg/L]
```

TDS是电导换算量。pH不能由TDS或HCO₃⁻可靠反推，不能在分享解码时自动生成。

## 6. 品鉴记录 `s`

| 短键 | 含义 |
|---|---|
| `i` | 记录ID |
| `d` | 日期 |
| `b` | 对应冲煮记录ID |
| `a` | 自动得分×10 |
| `u` | 主观得分×10 |
| `x` | 主观分差×10 |
| `q` | 感官节点与标签码 |
| `n` | 自然文字札记，最多300字 |
| `m` | 摘要标签 |

高频感官标签按数组位置编码；字典中不存在的自定义标签以 `~原文` 保存，防止数据静默丢失。

## 7. 安全与兼容

- 解码前必须限制编码长度，当前应用限制为16000字符；
- 解码结果必须通过普通对象、数组和数值范围检查；
- 分享数据不是加密数据，二维码和链接持有者可以读取内容；
- `LB8` 不包含私人联系方式和本机备注；
- v0.8解码器保留对v0.7 Base64 JSON旧链接的只读兼容；
- 未来改变字段语义时必须提升顶层 `v`，不能复用当前版本号。
