# LuckyBean 1.23D 识别契约检查点 2 测试报告

日期：2026-08-08  
检查点：`1.23D-recognition-contract.2`  
行为基线：`1.2.3-brewprofiles-integration-test`

## 本次关闭的问题

1. 日期确认逻辑从页面事件抽离为可复用、可单测的领域模块。
2. 确认页在需要人工处理时显示全部日期候选，包括原先自动识别的烘焙日期，避免隐形覆盖。
3. 选择一个新烘焙日期时自动取消其他烘焙日期；提交层仍执行唯一性校验。
4. 候选 ID、候选值和重复提交均进行校验，拒绝失效候选与页面篡改产生的日期。
5. 用户选择“全部忽略”后保持烘焙日期为空，不再恢复先前的自动候选。
6. 人工确认保存 `candidateId`、原文、图片角色、图片 ID、OCR block、标签证据、原 OCR 置信度和确认模块版本。
7. 人工确认不再把 OCR 置信度强行改写为 `1.0`。
8. 修复标签跨行泄漏：已经在本 OCR block 绑定日期的 `Best Before/MFG/PKD/EXP/Roast Date` 标签，不得继续影响下一 block 的批次或孤立日期。
9. 新增独立 `recognition-test.html` Web 验收页，支持输入 OCR 文本、查看全部候选、调整字段归属、解决日月歧义及检查最终来源记录。

## 当前可确认的结论

- 在现有 30 组黄金样本及新增确认决策回归中，非烘焙日期静默写入烘焙日期为 0。
- 多个烘焙日期不再静默选择；用户确认层与提交层均执行唯一性约束。
- 确认后的日期值、候选身份和来源证据可写入 `parseMetadata.dateReview`。
- Web 验收页文件和静态入口可访问，已进入 Service Worker 离线清单。

## 尚未关闭的门禁

- 现有黄金集仍以文本/结构化构造样本为主，不等同于 100 组匿名化真实豆袋图片。
- 本环境没有可用浏览器内核，因此未执行 Chrome/Edge 的真实点击、返回、刷新和保存自动化；不能将静态入口检查写成浏览器闭环。
- PP-OCR 模型尚未随仓库提供，拍照识别仍未完成 Android 真机闭环。
- Android WebView 与 iOS 浏览器的同输入一致性尚未验证。
- `recognition-test.html` 尚未发布为公网测试 URL。

阶段 B 的代码与本地验收页继续推进，但最终退出门禁仍保持不变：完成 100 组真实豆袋黄金集、真实浏览器/Android WebView 回归，并证明非烘焙日期误填和多日期静默错填均为 0。阶段 C 的推荐、分享、品鉴等业务模块尚未开始关闭。
